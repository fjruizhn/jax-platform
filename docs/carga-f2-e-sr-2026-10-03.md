## Metodología HTTP predeclarada

Cada corrida usa un worker, proveedor Ollama simulado en `127.0.0.1:17434`, y backend HTTP real en `127.0.0.1:18080`. La base aislada es MariaDB 12.3.3, con buffer pool de 128 MiB, 151 conexiones y puerto 13338. Se crean credenciales temporales nuevas con modo 0600; no se lee `/etc`, no se usa GPU, no se despliega y no se conecta una base o puerto de producción.

El escenario contiene 50 usuarios × 20 turnos y 5.000 filas filler. El conjunto exacto de concurrencias es `N=100/150/200/375/600`, correspondiente a `c=1/5/10/25/50`, con textos de 8k y 16k caracteres. Se ejecuta primero toda la serie de 8k y luego toda la de 16k; en cada tamaño hay tres repeticiones y se rota el orden de pares para reducir sesgo de calentamiento.

Se mide, no se impone como SLA, un p95 mayor a 500 ms. El calentamiento solo prepara el proceso y no altera ese criterio. El plateau de throughput se determina empíricamente; no representa una promesa de producción.

## Hallazgos operacionales conservados

Los deadlocks MariaDB 1213 pertenecen al proceso de memoria en segundo plano: F2-E-SR sumó 200 (17–55 por corrida), F2-D histórico 250 (16–84) y baseline 268 (16–81). No prueban que B9 sea fiable; se preservan como residual conocido y separado de la revalidación F2-E-SR. Las 11 notas de limpieza documentan incidentes de recuperación de matriz acotados al código MariaDB 1020 y realizados con conexión fresca. La reparación posterior reintenta, con rollback en la misma conexión, solo los códigos cerrados `1020`/`1205`/`1213`; las excepciones sin código fallan cerrado. Los dos caminos de fallo suave capturan únicamente `HTTPError` y `pymysql.Error`, y emiten trazas de advertencia saneadas; las pruebas usan `pytest.raises` para las rutas que deben propagar. La matriz y el hot path medidos no cambiaron. El hot path primario y único permanece indexado. La recuperación de arranque usa `Using temporary`/`Using filesort` en un `GROUP BY`; no se hace una afirmación de EXPLAIN sobre el sistema de archivos ni se extrapola ese plan al hot path.

En un venv mínimo nuevo, con `pytest`, `httpx`, `pymysql`, `python-jose`, `bcrypt` y sus constraints exactos, pasaron 89 pruebas totales, incluidas 15 focalizadas nuevas. El CI remoto del SHA nuevo sigue pendiente y no se declara verde aquí. Gitleaks pasó. El agregador estricto también revalidó la evidencia copiada, idéntica byte a byte al resumen guardado. Esta evidencia no autoriza un GO de producción.
